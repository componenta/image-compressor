# Componenta Image Compressor

Сжатие изображений без смены формата. [English documentation](README.md).

## Установка

```sh
composer require componenta/image-compressor
```

Требуются PHP 8.4+, расширения GD и EXIF, Componenta Config 4 и MIME Type Detector 2.

## Использование

Поставщик конфигурации регистрирует `ImageCompressor` и четыре встроенных обработчика GD. Получите сервис из контейнера или создайте его, передав `MimeTypeDetectorInterface` и коллекцию обработчиков.

```php
use Componenta\Image\ImageCompressionOptions;

$image = $compressor->compress($source, new ImageCompressionOptions(quality: 85));
$png = $compressor->compress($pngSource, new ImageCompressionOptions(compressionLevel: 7));
```

Источник — строка с байтами изображения (не путь к файлу) либо поток PSR-7. Результат `CompressedImage` содержит доступные только для чтения свойства `content`, `mimeType`, `extension` и вычисляемый размер `size` в байтах. Результат требует непустых байтов, конкретного MIME-типа изображения без параметров и допустимого расширения без начальной точки. MIME-тип и расширение приводятся к нижнему регистру; объект результата не проверяет сами байты и не авторизует путь к файлу.

## Форматы и параметры

JPEG, PNG, WebP и AVIF. Каждый встроенный компрессор принимает только собственный формат, включая поддерживаемые псевдонимы MIME-типа.

Доступность форматов зависит от сборки GD. Метод `supports()` учитывает исходный MIME-тип и наличие кодеков. Метод `canCompress($source)` проверяет возможность выбора обработчика и ограничение размера входных данных, а не полную корректность изображения.

- `quality` — качество JPEG, WebP и AVIF, от 0 до 100.
- `compressionLevel` — уровень сжатия PNG, от 0 до 9; не влияет на визуальное качество.
- `avifSpeed` — скорость кодирования AVIF, от 0 до 10; меньшие значения повышают степень сжатия.
- `onlyIfSmaller` — по умолчанию false. При true после успешного перекодирования возвращаются исходные байты, если новый результат не меньше. Исходные метаданные и дополнительные данные в конце файла могут сохраниться; не включайте этот режим, когда перекодирование обязательно.

Значения по умолчанию: JPEG — 82, WebP и AVIF — 80, PNG — уровень 6, скорость AVIF определяется GD. Неподдерживаемые параметры отклоняются.

## Потоки и ограничения ресурсов

Перематываемый поток читается с начала; его позиция восстанавливается при успешном выполнении и ошибке. Если само восстановление не удалось, операция и предварительная проверка выбрасывают `CompressionStreamPositionRestoreException` (подтип `CompressionException`); позиция больше не гарантируется. Исключение сохраняет причину ошибки восстановления и исходную ошибку чтения в свойстве `readFailure`. Неперематываемый поток читается один раз с текущей позиции, а предварительная проверка возвращает false, не потребляя данные. Оркестратор передаёт детектору и обработчику один набор байтов, в том числе для пользовательских реализаций.

По умолчанию `ImageCompressionLimits` ограничивает входные данные 32 МиБ, разрешение — 16 000 000 пикселей, ширину и высоту — 8192 пикселями, результат — 64 МиБ. Зарегистрируйте объект ограничений в контейнере зависимостей, чтобы штатные фабрики настроили оркестратор и встроенные обработчики совместно. При ручной сборке передайте один объект ограничений оркестратору и каждому обработчику: оркестратор ограничивает объём байтов, обработчик — размеры изображения и собственные ограничения байтов. Самостоятельно созданный или переопределённый обработчик сохраняет собственные настройки. Встроенные обработчики проверяют размер и заявленное разрешение до декодирования и ограничивают объём сохраняемых выходных данных. Оркестратор также отклоняет слишком большой результат пользовательского обработчика; такой обработчик самостоятельно ограничивает декодирование и выделение памяти.

Ограничения не гарантируют точный предел потребления памяти и времени нативными кодеками. Для недоверенных загрузок дополнительно нужны проверка входных данных, изоляция процессов и ограничение ресурсов.

## Корректность изображения и ошибки

Встроенные обработчики работают со статическими изображениями. GIF, APNG с признаком анимации, анимированный WebP и AVIF с заявленным признаком последовательности `avis` не поддерживаются. Ориентация JPEG из EXIF применяется до перекодирования. При преобразовании в JPEG прозрачность заменяется белым фоном. Палитра PNG не преобразуется без необходимости. GD не гарантирует сохранение метаданных, цветовых профилей, расширенного динамического диапазона и большой глубины цвета; компрессор отклоняет 16-битный PNG. Заголовок результата проверяется на формат и размеры, но повторное полное декодирование результата при каждой операции не выполняется.

Ошибки обработки представлены `CompressionException`. Некорректная регистрация или настройка ограничений вызывает `InvalidArgumentException`. Неожиданные программные ошибки не подавляются.

## Расширение и интеграция

Реализуйте `ImageCompressorInterface` для пользовательского обработчика. Выбирается первый зарегистрированный компрессор, поддерживающий определённый MIME-тип. Для добавления используется `addCompressor()`. MIME-тип результата должен соответствовать операции; пользовательский обработчик отвечает за корректность байтов.

Поставщик `Componenta\Image\ImageCompressorConfigProvider` указан в метаданных Composer для автоматического обнаружения. Фабрики используют зарегистрированный детектор или создают `FinfoDetector`. 

## Проверки

```sh
composer test
composer analyse
composer bench
```

Для измерений нужна сборка GD со всеми встроенными кодеками. PHPBench использует воспроизводимые синтетические изображения на 1, 4 и 12 Мп (в пределах ограничений), сравнивая строки и потоки. Переход с предыдущей версии описан в [UPGRADE.md](UPGRADE.md).

Процесс `Compare performance` сравнивает v1.0.1 и новую версию на одном исполнителе PHP 8.4 с эквивалентными параметрами кодеков и тремя изолированными измерениями на сценарий. Операции, не поддерживаемые v1, исключаются; потоки измеряются на 1 Мп. PHPBench показывает пик памяти под управлением PHP, а не полное потребление памяти процесса.
